# Firestore 구조

이 앱은 전체 상태를 한 문서에 저장하지 않는다. 화면에서 사용하는 기존 v10 `state`는 아래 컬렉션을 조합해 재구성한다.

| 컬렉션 | 문서 단위 | 핵심 내용 |
| --- | --- | --- |
| `tasks` | 수행업무 1건 | 일정, 상태, 담당자, 반복 식별자, 완료 이력 |
| `checklistItems` | 체크항목 1개 | 수행업무·업무 DB·연계규칙의 체크리스트 |
| `taskLinks` | 수행업무 1건의 연결 | 상위 업무, 계산 기준, 근무일/달력일, 마감 규칙 |
| `templates` | 업무 DB 1건 | 반복 주기, 자동생성 범위, 기본 일정 규칙 |
| `linkedRules` | 연계 단계 1개 | 1→2→3→4 단계별 시작·마감 계산 규칙 |
| `manualBlocks` | 매뉴얼 블록 1개 | 글 또는 비공개 Drive 사진의 파일 ID와 설명 |
| `owners` | 담당자 1명 | 이름, 마크, 색상, 정렬 순서 |
| `categories` | 분류 1개 | 이름, 색상, 정렬 순서 |
| `holidays` | 휴일 1일 | 날짜, 사유, 출처 |
| `settings` | 설정 묶음 | 화면·자동화 설정. 외부 API 키는 제외 |
| `generatedKeys` | 자동생성 키 1개 | 동일 반복 회차의 중복 생성을 막는 고유 잠금 |
| `changeLogs` | 저장 작업 1회 | 변경 대상·필드·사용자·시각. 수정·삭제 불가 |
| `meta` | 스키마 메타데이터 | 앱·스키마 버전 |

온라인 저장은 트랜잭션에서 원격 문서를 먼저 읽고, 로컬에서 실제로 달라진 필드만 병합한다. 따라서 서로 다른 기기에서 서로 다른 업무를 수정해도 전체 데이터가 마지막 저장본으로 덮이지 않는다. 오프라인에서는 같은 필드 패치를 원자적 배치로 로컬 큐에 기록하고, 연결이 돌아오면 Firestore가 전송한다.

자동생성 업무는 `generatedKey`와 안정적인 업무 ID를 사용한다. 날짜를 바꿀 때 새 회차를 만드는 대신 기존 업무 문서와 기존 자식 업무의 날짜만 갱신한다.
